# 聚光灯与补光灯的客户端光照

两种灯均使用客户端虚拟光源，不再放置 `minecraft:light`，补光灯灯体也不再产生服务端方块光。灯光只影响画面，不改变刷怪、作物生长等服务端光照判定；原版方块光没有 RGB 通道，因此落点仍是原版白光，聚光灯光柱保留原有颜色。

## 实现

- 灯具在客户端 BE tick 的入口注册；公共 tick 会在客户端提前返回，因此不能在 `TAIL` 注册。
- `ClientStageLighting` 为当前 `ClientLevel` 维护独立的原版 `BlockLightEngine`。每五 tick 从客户端灯具与 Create 运动结构的缓存灯具列表重新计算光源集合；相同落点合并，一盏灯移走时不会撤掉其他灯的贡献。
- 静态聚光灯沿用邻居红石信号；补光灯使用同步的 `POWERED` 方块状态。Create 运动结构上的聚光灯按现有光柱行为保持开启；补光灯沿用结构内保存的 `POWERED` 状态。Sable 灯具沿用其船体红石状态及跨空间射线。
- 补光范围仍由服务器 COMMON 配置决定，通过登录及配置重载时的小型数据包同步。聚光范围继续由 Create 的滚轮行为同步。
- 独立引擎只将虚拟位置当作发光源，真实方块仍提供原版透光和遮挡属性。光源所在的空 section 也分配存储及一层邻接 section，移除最后光源后释放。
- 客户端的普通光照引擎保留服务端数据。渲染读取单点亮度或整段 `DataLayer` 时，取普通层与虚拟层的最大值；合并数据按两个输入快照缓存，不写回任何输入。整段读取覆盖 Sodium 的取光路径，合并缓存支持工作线程读取。
- 光源位置变化仅检查新增和移除的位置；附近区块加载、卸载会合并为一次虚拟层重建。方块透光属性变化交给原版传播处理。读取缺失区块不会请求加载，Sable 的共享空区块哨兵也视为缺失。
- 切换世界或退出时丢弃虚拟层。Sable 源位置和命中位置分别保留原有坐标空间，未命中落点投影到世界空间。普通 Create 运动结构在世界空间计算落点。

## 旧存档迁移

旧 `PlacedLights` 只作清理记录。灯具的服务端 `onLoad` 会立即把记录交给每维度 `SavedData`，不依赖灯具进入 ticking 范围；卸载、拆除、组装时也有只转移记录的兜底，不在区块或船体拆卸过程中改方块。原坐标按其原有世界/plot 空间保留，不根据新灯具位置猜测或平移。

迁移只删除记录位置上精确匹配的非水浸、15 级原版光方块；其他等级、水浸光源以及后来替换的其他方块保留。即使记录格已经是空气，也会重检该旧光源曼哈顿半径 15 内的整个有效光照足迹，避免源格已暗、邻格保存数组仍亮的遗留。重检依据当前真实方块恢复光照，其他真实发光源会被保留。任务按 section 合并，每维度每 20 tick 最多处理 4 个 section；首次升级可能逐步收敛几秒，而非一帧完成。

旧源格及足迹邻区块未加载时，任务保持保存，等相应区块 FULL 可用后继续，不强制加载。重启后继续未完成的删除和重检任务；只有 `Positions`、没有新 `RelightSections` 的旧迁移队列也会自动补足修复足迹。

自动迁移的边界：没有任何 `PlacedLights` 或迁移队列记录的历史孤立光方块，无法与玩家放置的同状态光方块区分，因此不会全局扫描或删除所有 `light[level=15]`，也不会根据当前光束推测历史落点。若玩家后来在一个仍保留旧归属记录的同一格放回完全相同状态的光方块，旧格式同样没有标记可供区分。旧结构移动后、失去记录的光方块也不能安全推断新位置。这些情况需要明确位置及来源后再人工处理。

旧补光灯灯体的服务端亮度也可能已保存于区块数组中，因此首次加载会把灯体的整个旧光照足迹加入同一修复队列，不创建删除记录；Sable plot 使用其独立引擎。迁移标记保存于 BE，后续加载不会重复排队，正常新灯也只做一次。之后没有周期性的服务端照明计算。

## 验证

`gradlew.bat build` 包括信号网络回归、`legacyLightCleanupRegression`、`stageLightingHookRegression` 及 `stageLightLayerRegression`。迁移回归直接运行生产队列，覆盖 owner 未加载、FULL 延迟、失败重试、删除后重启、旧格式记录、正负坐标的完整足迹、section 预算和不删除无记录光源。注册回归只读取编译后的类字节码，检查客户端提前返回不会跳过光源注册；它不加载游戏类，能够复现并阻止 `TAIL` 注册遗漏。后者不启动或初始化游戏，验证真实 `DataLayer` 的全部 256 种亮度配对、4096 个位置、输入快照不被修改、服务端数据替换、虚拟层撤销及并发读取。Mixin 方法签名对照当前依赖字节码检查；实际 Mixin 应用和画面仍需启动客户端确认。

由用户启动客户端后检查：

1. 在暗处给两种灯通电，落点照亮；补光灯灯体周围也亮。断电、转向、调距离或拆除后，旧位置恢复；灯光落点实际仍是空气。
2. 两盏灯落在同一格，关掉其中一盏仍应亮，全部关闭后熄灭。放置和移除遮光墙，光照应按原版遮挡更新。
3. 让光照跨越区块边界，离开并返回、退出重进以及切换维度，不应留下光斑；在亮区更新普通火把，普通光与虚拟光都应保持正确。
4. 开启当前 Sodium/Iris 光影组合重复检查。实现接入原版光照数据，但尚未实测每个光影包；光影包自行计算的阴影和特殊发光材质属于其自身行为。
5. Sable 船照地面、照另一艘旋转船、移动以及删除船体后，光照应跟随并消失。普通 Create 运动结构也应随位置更新，移出灯具视野仍可照亮落点。
6. 使用多人服务器，故意把客户端补光范围配置设成不同值，应仍采用服务器值；服务端重新加载范围配置后，已放置的灯也应更新。
7. 在升级前点亮两种灯并保存，再用新版加载：原光方块应被清理；熄灯后服务器查询亮度不应再看到旧灯体或旧落点的照明。
